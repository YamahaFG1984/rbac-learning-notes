## 1. Tag 命名与分支

主干已有 `v0.1.0` ~ `v1.2.0`。本分支的 tag 一律加 **`fe-`** 前缀，避免与主干冲突：

```
main               v0.1.0 ... v1.2.0
feat/react-frontend    fe-v0.0.1-docs, fe-v0.1.0 ... fe-v1.0.0
```

**这个分支可能长期不合并**——它是一个平行的交付形态，不是主干的下一步。
所以 tag 空间必须独立。

### 每个 tag 的硬性要求

同后端（见 [`../../CLAUDE.md`](../../CLAUDE.md) 第 8 节），外加三条前端特有的：

| # | 要求 |
| --- | --- |
| 1 | `cd frontend && npm install && npm run dev` 能起来 |
| 2 | `npm run build` 通过（TS 类型检查在这里） |
| 3 | 🔒 **后端 `pytest` 仍然全绿**（347 个）——不能为了前端破坏后端 |
| 4 | 🔒 **`git diff main HEAD -- apps/rbac/services.py` 为空** |

第 3、4 条每个 tag 都要跑。**它们是本阶段的护栏**。

## 4. 两个刻意留下的中间态

延续主干的做法（[`../03-实施计划.md`](../03-实施计划.md) 第 5 节）：

| Tag | 缺什么 | 在哪补上 | 为什么这么安排 |
| --- | --- | --- | --- |
| `fe-v0.4.0` | 菜单写死、无路由守卫 | `fe-v0.7.0` / `fe-v0.8.0` | 让「动态路由 + 动态菜单」的 diff 只讲这一件事。**和后端 `v0.8.0` 是同一个手法** |
| `fe-v0.9.0` ~ `fe-v0.12.0` | 权限快照不会自动更新 | `fe-v0.13.0` | 让你亲身体会「撤权后按钮还在」这个 SPA 特有的问题——**模板版根本不存在这个现象** |

第二个中间态尤其值得停下来体验：

> 用 `superadmin` 打开后台改 `cs_manager` 的权限，
> 同时用 `cs_manager` 开另一个浏览器窗口停在工单列表页。
>
> **模板版**：刷新 → 按钮消失。
> **`fe-v0.12.0` 的 SPA**：怎么点都不消失，除非按 F5 重载整个应用。
>
> 这就是 `fe-v0.13.0` 要解决的问题。先看见它。

## 5. 贯穿本阶段的几条原则

### 前端的一切权限判断都只是体验

| 出现位置 | 形态 |
| --- | --- |
| `fe-v0.7.0` | 路由守卫拦住无权限页面 |
| `fe-v0.8.0` | 菜单不渲染 |
| `fe-v0.9.0` | 按钮不渲染 |

**这三层加起来，安全价值为零。** `fe-v0.16.0` 的 E2E 会用一条测试证明：
绕过前端直接调 API，后端照样拦住——**前端做的一切它都不需要**。

### 权限规则只能有一处实现（后端）

| 反例 | 为什么错 |
| --- | --- |
| `if (user.dept.id === row.dept.id)` | 复制了数据权限规则，且只覆盖 `DEPT_ONLY` 一种 |
| `if (user.roles.includes('cs_manager'))` | 把角色编码硬编码进前端 |
| 前端对列表再过滤一遍 | 分页和统计立刻对不上（[F-ADR-015](02-设计文档.md)） |

### 让默认状态是安全的（前端版）

| 位置 | 形态 |
| --- | --- |
| `fe-v0.6.0` | profile 未加载完成前**不渲染任何业务界面** |
| `fe-v0.7.0` | 路由表里没有的路径 → 403，不是渲染出来再拦 |
| `fe-v0.9.0` | `<Can>` 的默认行为是**不渲染**，要显示必须有权限码 |
| `fe-v0.12.0` | 权限码类型为 `PermCode`，写错的字符串**编译不过** |

## 6. 学习自检清单

### 认证与传输

- [ ] 能说清同域部署下「为什么还要 JWT」，以及我们为什么选了 Session
- [ ] 能解释 `CSRF_COOKIE_HTTPONLY = True` 为什么**不提供实质防护**
- [ ] 能说出 httpOnly Cookie 换来了什么、又必须付出什么（同域 + CSRF）
- [ ] 能在浏览器控制台验证 `document.cookie` 里没有会话凭证

### 状态与数据

- [ ] 能判断一份数据属于「服务端状态」还是「客户端状态」
- [ ] 能说出权限数据为什么既要 Query 管又要进 Zustand
- [ ] 能说出为什么组件不能自行推断权限（举出两个具体反例）

### 路由与渲染

- [ ] 能说出动态注册路由的时序陷阱，以及刷新页面为什么会 404
- [ ] 能说出前端路由守卫为什么不是安全边界，且比隐藏按钮更容易造成错觉
- [ ] 能说出 403 跳登录页会造成什么后果

### SPA 特有

- [ ] 能说出「权限撤销后前端按钮还在」这个问题在模板版为什么不存在
- [ ] 能设计权限变更的感知机制，并说出所选方案的延迟与代价
- [ ] 能说出数据权限范围外为什么返回 404，以及前端该怎么展示

### 总检验

- [ ] `git diff main HEAD -- apps/rbac/services.py` 为空
- [ ] 能写出一条 E2E 测试，证明前端权限判断全部是体验

## 7. 与主干的关系

```
main ──── v1.2.0 ──────────────────────────────▶ （继续演进后端）
             │
             └── feat/react-frontend ── fe-v0.0.1-docs ... fe-v1.0.0
```

**本分支对后端的改动全部限制在适配层**（PRD 第 4 节的 BE-1 ~ BE-7），
且每个 tag 都用 `FAC-4` + 后端全量测试守住。

如果将来要合并回主干，冲突面应该只有：
`config/urls.py`、`config/settings/*.py`、`apps/rbac/api/`、`apps/rbac/models.py`（两个新字段）。
**`apps/rbac/services.py` 不在其中——那正是重点。**
