## 五、⚠️ 容易写错的地方

### 1. 「同域」不是「同一台机器」

第一节第 1 问的答案。

```
前端 http://localhost:5173   ┐
                             ├─ 不同源！Cookie 默认不会带过去
后端 http://localhost:8000   ┘
```

浏览器的同源策略看的是 **协议 + 主机 + 端口**，端口不同就是跨域。

所以**必须让浏览器认为只有一个源**：所有请求都发给 `:5173`，
由 Vite 把 `/api/*` 转发到 `:8000`。浏览器全程只看到一个源，
Cookie 自然就带上了，也不需要 CORS。

生产期同理，只是把 Vite 换成 Nginx。

### 2. `changeOrigin` 要设 `false`

`changeOrigin: true` 会把转发请求的 `Host` 头改成目标地址（`127.0.0.1:8000`）。

对我们有害，因为 Django 的 CSRF 校验会比对 `Origin`/`Referer` 与 `Host`。
改了之后可能出现「CSRF verification failed」，而且**报错信息完全指不到真正原因**。

设 `false` 保持原始 Host，Django 看到的就是浏览器真正访问的那个源。

### 3. 后端路由迁移会打断一批测试

模板版路由从 `/accounts/...` 变成 `/django/accounts/...`。

**但绝大多数测试不会受影响**——因为它们用的是 `reverse("accounts:user_list")`
而不是硬编码路径。这是主干当初坚持用 URL name 的红利。

会受影响的只有少数硬编码路径的地方，比如：

```python
resp = client.get(f"/rbac/roles/{role.pk}/permissions/")   # ← 要改
```

跑一遍 `pytest` 就知道有几处。**顺手把它们全改成 `reverse()`**，
这是一次免费的技术债清理。

### 4. `frontend/dist/` 必须进 `.gitignore`

第一节第 4 问的答案。

后端 `ADR-015` 让 Tailwind 产物入库，前提是「一个几十 KB 的 CSS 文件，
入库能省掉 `npm install` 这一步」。

React 的前提完全不同：几百个 chunk、几 MB、每次 hash 都变，
而且**入库也省不掉 `npm install`**——要改代码还是得装依赖。

> **同一个项目里两个相反的决定，理由都成立。**
> 教条地套用前一个决定就会错。判断依据永远是**前提有没有变**。

### 5. `withCredentials: true` 不能忘

axios 默认不带 Cookie。同域下浏览器本来会带，但 axios 的 XHR 需要显式开启。

忘了它的表现是：登录接口成功，之后所有请求都 401——因为 Cookie 根本没发出去。

## 六、卡住了看这里（渐进提示）

<details>
<summary><b>提示 1：vite.config.ts 完整版</b></summary>

```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import path from 'node:path'

const backend = 'http://127.0.0.1:8000'

// 同域是 httpOnly Cookie 方案的硬性前提（F-ADR-002）。
// 浏览器只访问 :5173，Vite 把后端路径转发过去——全程单一源，
// 既能带 Cookie 也不需要 CORS。
const proxyTargets = ['/api', '/django', '/admin', '/static']

export default defineConfig({
  plugins: [react()],
  resolve: { alias: { '@': path.resolve(__dirname, 'src') } },
  server: {
    port: 5173,
    proxy: Object.fromEntries(
      proxyTargets.map((p) => [
        p,
        {
          target: backend,
          // ⚠️ 必须 false：改写 Host 会让 Django 的 CSRF Origin 校验失败，
          //    而且报错信息完全指不到真正原因。
          changeOrigin: false,
        },
      ]),
    ),
  },
})
```
</details>

<details>
<summary><b>提示 2：后端路由拆分</b></summary>

```python
# config/template_urls.py —— 模板版路由收拢到这里
from django.urls import include, path

urlpatterns = [
    path("accounts/", include("apps.accounts.urls")),
    path("rbac/", include("apps.rbac.urls")),
    path("tickets/", include("apps.tickets.urls")),
    path("audit/", include("apps.audit.urls")),
]
```

```python
# config/urls.py
urlpatterns = [
    path("admin/", admin.site.urls),
    path("api/v1/", include("config.api_urls")),
    # 模板版整体迁到 /django/，把根路径让给 React（F-ADR-001 并存）
    path("django/", include("config.template_urls")),

```

各 app 内部的 `app_name` 和 `url_name` 一个字都不用改，
所以模板里的 `{% url %}` 全部自动生效。

## 九、延伸思考

1. **如果必须跨域怎么办？**（前端在 CDN、API 在独立域名）

   要用 `SameSite=None; Secure` + CORS `credentials: true` + 精确的 `Access-Control-Allow-Origin`。
   查一下这条路会打开哪些新问题（提示：`SameSite=None` 意味着什么？浏览器对第三方 Cookie 的政策正在怎么变？）

2. **Vite proxy 只在开发期有效。** 生产期 Nginx 配置长什么样？
   写一份出来（`fe-v1.0.0` 会需要）。

3. **两套前端并存后，「首页」应该是谁？**
   我们让 React 占 `/`，模板版退到 `/django/`。反过来行不行？
   想想哪个决定更容易在将来后悔。

4. 后端测试从 347 个变成多少个了？如果一个都没红，说明什么？
   如果红了十几个，说明当初哪里没做好？
