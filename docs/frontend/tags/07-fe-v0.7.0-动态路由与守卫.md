## 四、实现步骤

**Step 1** — `import.meta.glob` 收集 `src/pages/**/*.tsx`。

**Step 2** — `buildRoutes`：遍历 menus，把 `routePath` + `component` 转成 `RouteObject`。

**Step 6** — 逐条验证第七节的时序用例。

## 五、⚠️ 容易写错的地方

### 🔴 1. 刷新页面时的时序陷阱

第一节第 2 问的答案，也是本 tag 的核心难点。

```
F5 → React 挂载 → 路由表是空的 → 匹配不到 /tickets/42 → 渲染 404
                       ↑
                 profile 还在路上（100~300ms）
```

用户看到的是「刷新一下就 404 了」，这是 SPA 动态路由最经典的 bug。

**解法**：`fe-v0.6.0` 的 `AuthBootstrap` 已经保证了 profile 加载完才渲染 children，
所以只要**把 `AppRouter` 放在 `AuthBootstrap` 内部**就行：

```tsx
<AuthBootstrap>        {/* status === 'unknown' 时只渲染 loading */}
  <AppRouter />        {/* 到这里 menus 一定有值 */}
</AuthBootstrap>
```

⚠️ 但 `/login` 路由必须在**外面**——未登录时也要能访问它。
所以路由被拆成两段：

```
公开路由（静态）：/login、/403、/404
     └── 受保护区（动态）：AuthBootstrap → AppRouter
```

### 🔴 2. `useMemo` 的依赖写错会无限重建 router

```tsx
// ❌ menus 是数组，每次 store 更新都是新引用 → router 每次重建 → 页面闪烁 + 状态丢失
const router = useMemo(() => createBrowserRouter(buildRoutes(menus)), [menus])
```

Zustand 的 selector 如果返回新对象，每次渲染都会变。要么保证引用稳定，
要么用一个**内容指纹**做依赖：

```tsx
const menuKey = useMemo(
  () => menus.map((m) => m.routePath ?? m.id).join('|'),
  [menus],
)
const router = useMemo(() => createBrowserRouter(buildRoutes(menus)), [menuKey])
```

表现很迷惑：页面看起来能用，但输入框每敲一个字就失焦——因为整个 router 重建了。

### 3. 无权限路径跳 403，不是 404

第一节第 3 问。

| 情形 | 应该 |
| --- | --- |
| `/system/users`（存在，但你没权限） | **403** |
| `/nonexistent-page`（根本不存在） | 404 |

动态注册的副作用是**两者都匹配不到路由**，所以默认都会掉进 `*` 兜底 → 404。

这是错的：用户会以为「链接失效了」而不是「我没权限」，于是去问 IT 为什么链接坏了。

**解法**：兜底路由里判断——这个路径是否存在于「全部已知路由」中：

```tsx
// 需要一份「系统里所有路由」的清单（不是当前用户有权限的那份）
const isKnownPath = ALL_KNOWN_PATHS.some((p) => matchPath(p, location.pathname))
return isKnownPath ? <Forbidden /> : <NotFound />
```

⚠️ 这需要前端知道「系统里有哪些页面」——**这是信息泄露吗？**

严格说是的（攻击者能枚举出系统有哪些页面）。但：
- 这个信息价值极低（页面路径不是秘密）
- 换来的是明确的用户提示

**接受，但要知道自己在交换什么。** 洁癖一点的做法是全部返回 404
（和后端 `ADR-009` 对数据的做法一致），代价是用户体验。

我们选前者，因为**页面存在性**和**数据存在性**的敏感度不同。

### 🔴 4. 路由守卫**不是**安全边界

第一节第 4 问的答案：**没有区别，都只是体验。**

```ts
if (!perms.includes(to.meta.perm)) return '/403'
```

这行代码挡不住任何攻击者——`perms` 就在他的浏览器内存里，
控制台改成 `['*']` 只需几秒；而且他根本不必用你的前端。

> 模板版：「攻击者不点你的按钮，他直接发请求。」
> **SPA 版：「攻击者不用你的路由，甚至不用你的前端。」**

⚠️ **路由守卫比按钮隐藏更容易造成错觉**，因为它写起来太像鉴权了。
在 `PermissionGate.tsx` 顶部必须写清楚这一点，`fe-v0.16.0` 会用 E2E 证明它。

### 5. 动态注册 + 守卫，两个都要

只动态注册：漏注册的路由没人管；某些静态路由（如 `/profile` 个人中心）不在菜单里。
只用守卫：所有页面组件都进 bundle，系统结构完全暴露。

**两个都做**（F-ADR-007 方案 c）。守卫是兜底，不是主力。

### 🔴 5b. 两个实现时才撞上的问题

**(1) 详情页不在菜单里 —— 动态注册覆盖不到**

`/tickets/:id` 是从列表点进去的，它**不是菜单项**，后端的 `menus` 里没有它。
只做动态注册的话，详情页根本没有路由。

**这正好证明了 F-ADR-007 选「动态注册 + 守卫兜底」是对的**：
非菜单页面用一份静态路由表（`staticRoutes.tsx`）+ `PermissionGate`。

**(2) 🔴 AntD 会给两个汉字的按钮自动插空格**

`<Button>登录</Button>` 实际渲染成 **`登 录`**（`autoInsertSpace` 默认开启）。

后果：任何按文本查找按钮的代码都失效——
`getByRole('button', { name: '登录' })` 找不到元素，
而报错只说「找不到」，**完全指不到真正原因**。我在这上面卡了一轮。

在 `ConfigProvider` 全局关掉：

```tsx
// ⚠️ AntD 6 里它在 button 命名空间下，不是顶层属性
<ConfigProvider locale={zhCN} button={{ autoInsertSpace: false }}>
```

让 DOM 里的文本和源码里写的一致——否则这个坑会在每一个新写的测试里重现。

### 6. `import.meta.glob` 的路径必须是字面量

```ts
// ✅
const modules = import.meta.glob('../pages/**/*.tsx')

// ❌ Vite 静态分析不了，运行时拿到空对象
const dir = '../pages'
const modules = import.meta.glob(`${dir}/**/*.tsx`)
```

同 Tailwind 扫描的道理——**构建工具做的是静态分析，拼接出来的东西它看不见**
（后端 `v0.8.0` 陷阱 4 是同一类问题）。

```ts
// ⚠️ 路径必须是字面量——Vite 是静态分析，拼接的路径它看不见
const modules = import.meta.glob('../pages/**/*.tsx')

export function resolveComponent(component: string) {
  // component 形如 "tickets/List" → "../pages/tickets/List.tsx"
  const key = `../pages/${component}.tsx`
  const loader = modules[key]
  if (!loader) {
    // 后端配错了 component。不能让整个应用崩——降级为一个提示页，
    // 同后端 v0.11.0 对 NoReverseMatch 的处理。
    console.error(`[router] 找不到组件：${key}`)
    return null
  }
  return lazy(loader as never)
}
```

```tsx
export function AppRouter() {
  const menus = useAuthStore((s) => s.menus)

  // ⚠️ 用内容指纹做依赖，不要直接用数组——否则 router 会反复重建
  const fingerprint = useMemo(

    [fingerprint],
  )

  return <RouterProvider router={router} />
}
```

<details>
<summary><b>提示 3：PermissionGate</b></summary>

```tsx
/**
 * 路由级权限守卫。
 *
 * ⚠️ 这**不是**安全边界，只是体验优化。
 *    perms 就在用户的浏览器内存里，改成 ['*'] 只需要几秒；
 *    而且攻击者根本不必用这个前端。
 *
 *    唯一的安全边界是后端的 HasPerm + ScopedQuerysetMixin。
 *    fe-v0.16.0 有一条 E2E 专门证明这一点。
 */
export function PermissionGate({ perm, children }: Props) {
  const can = usePermission()
  if (perm && !can(perm)) return <Navigate to="/403" replace />
  return <>{children}</>
}
```

## 九、延伸思考

1. **用例 10 让你亲手验证了「前端守卫可被绕过」。**
   那我们为什么还要做守卫？（提示：它挡的不是攻击者，是**误操作和坏链接**。）

2. 动态注册让 bundle 不包含无权限页面吗？**其实不一定**——
   `import.meta.glob` 默认是懒加载（生成独立 chunk），
   但 chunk 文件仍然在服务器上，URL 可以被猜到。
   查一下 `import.meta.glob` 的 `eager` 选项，想想两种模式的差别。

3. **多标签页**：用户在标签页 A 被撤权，标签页 B 的路由表还是旧的。
   `fe-v0.13.0` 会解决数据层，但**已注册的路由**要怎么撤销？
   （提示：`menus` 变化会触发 router 重建——这是好事还是坏事？
   重建时用户当前所在页面会怎样？）

4. 我们让「路径存在但无权限」跳 403，暴露了系统有哪些页面。
   后端对**数据**的做法是统一 404（`ADR-009`）。
   **为什么两处的结论不同？** 说清楚「页面存在性」和「数据存在性」的敏感度差异。
