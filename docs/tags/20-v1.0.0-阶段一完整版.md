## 五、⚠️ 要点

### 1. `seed_demo` 必须幂等或提供 `--flush`

反复跑不能产生重复数据。两种做法：
- `--flush`：先清空相关表再生成（简单，推荐）
- 幂等：用 `get_or_create`（复杂，但不会误删数据）

⚠️ `--flush` 要有**确认提示**，防止有人在真实环境误跑。

### 2. `bulk_create` 会绕过 `save()`

**回想 `v0.3.0` 延伸思考 2 的预言**：用 `bulk_create` 批量建部门，`path` 会全空——因为 `bulk_create` 不调用 `save()`。

现在就是你遇到它的时候。解法：
- 部门数量少，逐个 `create()`
- 或者 `bulk_create` 之后调用 `rebuild_dept_path`

工单 80 条可以 `bulk_create`（它没有 `save()` 里的特殊逻辑），但要注意 `TimestampedModel` 的 `auto_now_add` 是能正常工作的。

### 3. `--check-templates` 的正则要保守

```python
PERM_CODE_RE = re.compile(r"['\"]([a-z][a-z0-9_]*:[a-z][a-z0-9_]*:[a-z][a-z0-9_]*)['\"]")
```

只匹配符合三段式格式的字符串。太宽会误报（比如 CSS 里的 `background:url:xxx`），太窄会漏报。

**这个功能解决的是 `v0.10.0` 陷阱 3 留下的问题**：模板里的权限码 typo 静默失败。

⚠️ 它只能发现「模板里有但库里没有」的，发现不了「库里有但模板里写错成另一个存在的码」。**部分解决好过不解决。**

顺便：也扫一遍 `apps/**/views.py`？装饰器里的权限码同样可能 typo——不过那些通常用常量类，风险小。想想值不值得。

### 4. 冒烟脚本要能自动化

```bash
#!/usr/bin/env bash
set -uo pipefail
TAGS=$(git tag -l 'v0.*' 'v1.*' | sort -V)
FAILED=()
for tag in $TAGS; do
    git checkout -q "$tag" 2>/dev/null || { FAILED+=("$tag:checkout"); continue; }
    rm -f db.sqlite3
    python manage.py migrate --noinput >/dev/null 2>&1 || { FAILED+=("$tag:migrate"); continue; }
    python manage.py check >/dev/null 2>&1 || { FAILED+=("$tag:check"); continue; }
    echo "✓ $tag"
done
git checkout -q main
[ ${#FAILED[@]} -eq 0 ] && echo "全部通过" || printf '✗ %s\n' "${FAILED[@]}"
```

⚠️ `v0.1.0` 是个例外——它**故意不能 migrate**（那时还没有 User 模型和迁移文件）。脚本要特殊处理它。

**这个例外本身就是个教学点**：自动化脚本遇到「刻意的例外」时，是改脚本还是改设计？这里显然是改脚本——因为那个例外是有意义的。

### 5. 文档与实现的同步

`CLAUDE.md` 的规矩：**代码与文档不一致时，先改文档再改代码。**

现在逐条检查：
- PRD 里的 P0 需求，有没有实现时发现不合理而改了做法的？
- 设计文档的 ADR，有没有实践中推翻的？
- 实施计划里各 tag 的描述，和实际做的一致吗？

**如果某个 ADR 在实践中被证明是错的，不要偷偷改代码——在文档里记下「当初这么决定，实践中发现 X，所以改成 Y」。** 这个记录比正确的结论更有价值。

```python
class Command(BaseCommand):
    help = "生成演示数据（部门树 / 角色 / 用户 / 工单）"

    def add_arguments(self, parser):
        parser.add_argument("--flush", action="store_true", help="先清空再生成")

    @transaction.atomic
    def handle(self, *args, **opts):
        if opts["flush"]:
            if input("将清空全部演示数据，确认？(yes/no) ") != "yes":
                self.stdout.write("已取消"); return
            Ticket.objects.all().delete()
            UserRole.objects.all().delete()
            RolePermission.objects.all().delete()
            RoleDepartment.objects.all().delete()
            Role.objects.all().delete()
            User.objects.filter(is_superuser=False).delete()
            Department.objects.all().delete()

        call_command("sync_permissions")        # 先保证权限点在库里

        depts = self._create_departments()      # ⚠️ 逐个 create，不用 bulk_create
        roles = self._create_roles(depts)
        users = self._create_users(depts, roles)
        self._create_tickets(depts, users)

        self.stdout.write(self.style.SUCCESS("演示数据生成完毕，统一密码：demo1234"))
```

<summary><b>提示 2：--check-templates</b></summary>

```python
def check_templates(self):
    known = set(
        Permission.objects.exclude(code__isnull=True).values_list("code", flat=True)
    )
    problems = []
    for path in Path(settings.BASE_DIR / "templates").rglob("*.html"):
        text = path.read_text(encoding="utf-8")
        for m in PERM_CODE_RE.finditer(text):
            code = m.group(1)
            if code not in known:
                line = text[: m.start()].count("\n") + 1
                problems.append(f"{path.relative_to(settings.BASE_DIR)}:{line}  {code}")
    if problems:
        self.stdout.write(self.style.ERROR(f"发现 {len(problems)} 个未知权限码："))
        for p in problems:
            self.stdout.write(f"  {p}")
    else:
        self.stdout.write(self.style.SUCCESS("模板中的权限码全部有效"))
    return len(problems)
```

带上文件名和行号——**报错信息能直接定位，才有人愿意用。**
