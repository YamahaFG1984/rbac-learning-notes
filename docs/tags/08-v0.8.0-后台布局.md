## 三、接口契约（必须与我的实现对齐）

### `base.html` 的 block 名

```django
{% block title %}{% endblock %}
{% block page_title %}{% endblock %}      {# 内容区顶部的大标题 #}
{% block page_actions %}{% endblock %}    {# 大标题右侧的操作按钮区 #}
{% block content %}{% endblock %}
{% block extra_js %}{% endblock %}
```

### 模板片段路径

```
templates/_partials/_sidebar.html
templates/_partials/_topbar.html
templates/_partials/_messages.html
templates/_partials/_table.html
templates/_partials/_pagination.html
templates/_partials/_form_field.html
```

> 下划线前缀表示「片段，不单独渲染」，这是 `CLAUDE.md` 的命名约定。

| 元素 | 类 |
| --- | --- |

## 五、⚠️ 容易写错的地方

### 1. `DEBUG=True` 时看不到自定义错误页

Django 在 `DEBUG=True` 时会显示自己的调试页面，你的 `404.html` 根本不会被渲染。

**验证方法**：临时把 `dev.py` 里的 `DEBUG` 改成 `False`，同时要设 `ALLOWED_HOSTS = ["*"]`（否则会 400），然后跑 `runserver --insecure`（`--insecure` 让 runserver 在 DEBUG=False 时仍然提供静态文件）。

验证完记得改回来。

### 2. `handler403` 等要写在**根** `urls.py`

```python
# config/urls.py
handler403 = "config.views.custom_403"
handler404 = "config.views.custom_404"
handler500 = "config.views.custom_500"
```

写在 app 的 `urls.py` 里不生效。而且这些变量的值是**字符串路径**，不是函数对象。

### 3. `500.html` 里不能用 context processor 提供的变量

500 页面在渲染时，请求上下文可能已经崩了。Django 用 `render_to_response` 渲染它，**不走 context processor**。

所以 `500.html` 里不能有 `{{ user }}`、不能 `{% include %}` 依赖 context 的片段——写一个纯静态的页面。

**这个坑的表现是：出 500 时页面又崩一次，日志里只有一个二次异常**，极难排查。

### 4. Tailwind 扫不到动态拼接的 class

```python
# ❌ Tailwind 扫不到，样式不会被打包
color = "red" if error else "green"
css_class = f"text-{color}-600"
```

Tailwind 是**静态扫描**源文件里的字符串。拼接出来的 class 名它看不见。

正确做法是写完整的类名：
```python
css_class = "text-red-600" if error else "text-green-600"
```

### 5. 别忘了重新构建 CSS

`CLAUDE.md` 的 DoD 里有这条。改了模板不重新 build，新用的 class 不会在产物里，样式就丢了。

## 九、延伸思考

1. **第一节第 2 问的答案**：为什么把「写死菜单」单独作为一个 tag？

   因为 `v0.11.0` 要做的是「动态菜单」。如果布局和动态菜单在同一个 tag 里完成，那个 diff 会是「300 行模板 + 80 行菜单算法」混在一起，你根本看不清动态菜单到底改了什么。

   拆开之后，`v0.11.0` 的 diff 里只有菜单逻辑——**干净得能一眼看完**。

   > **tag 的切分要让 diff 讲故事。** 这是本项目组织代码的核心方法，你在后面还会看到两次（`v0.13.0`→`v0.14.0`、`v1.1.0`→`v1.2.0`）。

2. 现在侧边栏是写死的，意味着**所有登录用户看到的菜单一模一样**——包括那些他根本点不进去的页面。

   在你的浏览器里体验一下：用一个没有角色的用户登录（`v0.6.0` 已经能分配角色了），点一下「角色管理」。会发生什么？

   （现在会正常打开——因为 `v0.9.0` 的视图鉴权还没做。**这就是下一个 tag 要补的洞。**）

3. Tailwind 的产物入库让 diff 有噪音。除了 `.gitattributes` 标记，还有什么办法？

   （提示：`git config diff.generated.binary true`、或者在 `.gitattributes` 里直接标 `-diff` 让 git 不显示它的内容差异。试试哪种更顺手。）
